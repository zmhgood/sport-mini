# 2026-10-14 自适应布局回归

体验版仍为用户确认的 `1.0.20261013.2`。本次修复仅在本地与 Git，未上传新体验版、未部署服务器、未提交审核。

## 修复范围

同一套自适应布局，无按具体机型分支的 CSS：

- 首页家庭弹层打开时隐藏底栏，关闭/选择/离开时恢复。长家庭列表独立滚动，固定底部加入按钮；加入入口显式传 `type=join`。
- 创建目标动作列表使用 `scroll-view`，确认区固定；长成员、动作及目标肌肉文字换行，避免挤压操作区。
- 登录、资料编辑、加入家庭、目标详情、锻炼提交/进度控制的相关按钮至少44px；页面底部补安全区。
- 资料页性别字段占据剩余宽度并靠右，备注标题使用可用宽度避免孤字换行。
- 进度数据找不到当前用户时显式写入 `null`，避免微信忽略 `undefined` 更新而留下旧进度。修复前两项测试失败，修复后三项通过；追加短视口与320px官方模拟器回归。
- 文本、数字和多行表单补 `cursor-spacing=96`，为真机键盘上推留空间；实际键盘效果尚需手机验证。

断言数是每轮检查次数，并非独立业务用例数量；初始化页面的检查数可能略有差异。子页面矩阵含原15个场景（加入/创建及锻炼填写/进度查看分开）；最终脚本另加空进度刷新场景，结合三个主页面覆盖全部16个登记页面。字体26是模拟器设置，不代表真实系统字体缩放已验收。短视口为自定义390×520屏幕，实际页面390×452，用于空间压力测试。

390px返回已独立确认：通过开发者工具「模拟操作 → 返回」回到首页，可见窗口显示首页与三个底栏入口；SDK回读仅有首页、`hidden=false`、`selected=0`，无业务写入。无需针对390px添加导航补丁。

## 工具异常与未完成边界

早期存在SDK页面栈、可见渲染不一致、后台动画未完成及超时。失败轮次保留在JSON摘要，恢复原项目/新自动化端口后复跑；没有把成功回调直接当作通过。长协议页滚到末尾时，上边缘移出视口属于正常滚动，测试改为末尾可达；媒体另检查整图在视口内。

本轮全部使用虚构资料、家庭和动作，请求模拟，非GET业务请求拒绝并记录。没有登录、保存资料、加入家庭、创建目标或提交锻炼。软件键盘、真实iOS/Android触摸与字体、分享直达权限、GIF/视频解码及线上网络需要后续真机测试。
