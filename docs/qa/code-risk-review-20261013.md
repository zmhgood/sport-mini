## 为什么需要重建

先前测试主要证明了页面在合成成功响应下能操作，以及加载/失败/空态、部分客户端去重。家庭删除再加入、数据库唯一约束、角色失效、跨目标引用、事务中途失败和统计对账没有形成完整闭环。

## 测试方法与影响矩阵

| 维度 | 必测状态/转换 | 判定证据 |
| --- | --- | --- |
| 生命周期 | 创建→首次加入→参与目标→部分/全部完成→退出/移除→旧URL拒绝→重新加入→历史保留 | API、成员/进度自然键、角色、独立 SQL 对账、两端/admin回读 |
| 权限 | 上述7类身份 × 家庭/目标/进度读写；跨家庭、同家庭不同目标；移除前后同Token | 拒绝响应＋所有相关表无新写入；个人历史按确认规则保留 |
| 幂等与并发 | 双击、串行3次、并发10次、响应丢失重试、两端同时修改 | 一份逻辑明细；统计不增加；冲突策略明确，不依赖客户端按钮 |
| 事务 | 创建家庭/目标、转移管理员、进度/流水/日汇总任一中间写失败 | 要么整体成功，要么回滚/明示可恢复，不留半成品 |
| 统计 | 个人/家庭/参与者/目标/动作/组数/天数/秒与分钟；多家庭同日；跨日周；删除与历史 | 手算固定数据→独立SQL→API→页面/admin四层对账 |
| 输入/契约 | 0/负数/超限、空/超长、坏JSON、未知ID、未实现接口、默认分页 | 服务端验证；真实空、错误、加载分离；无假成功 |
| UI/媒体 | 多尺寸、安全区、完整图、真实GIF帧、视频、失败重试、长文本、Tab/按钮 | 官方渲染与真机证据；Decisions只辅助视觉判断 |

未知产品规则不能默默猜：估算时长、历史分母快照、家庭进度聚合和允许谁修改/删除目标仍标为草案。不阻塞已确认的权限撤销、历史保留和完成次数测试。
